## Decisions Made

### 1. Two Registries, One System
**Decision:** Keep both REGISTRY.md (human-readable) and doc-map.md (machine-readable)
**Why:** Allows flexible queries — humans read registry, machines read doc-map

### 2. Never Modify Superpowers Artifacts
**Decision:** `/docs/superpowers/` is tool-managed; doc-doctor only catalogs
**Why:** Preserves skill autonomy, avoids conflicts, keeps workflow clean

### 3. Navigation Guide is Manual
**Decision:** nav.md is user-curated template, not auto-generated
**Why:** Navigation design reflects UX goals, not mechanical rules; more stable than auto-generated boilerplate

### 4. Progressive Disclosure by Scope
**Decision:** Three tiers (agent → reference → artifact) with explicit navigation paths
**Why:** Agents can find info at the right depth without loading full context; reduces cognitive load and token waste

### 5. Registry as Cross-Reference Index
**Decision:** REGISTRY.md is the single source of truth for "what's related to what"
**Why:** Prevents duplicated links in module docs; single place to update when references change
