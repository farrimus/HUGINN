# Frontend Architecture — React Companion App

## Overview

The companion chat interface is a **React application** served as static files from the FastAPI backend. It connects to EVE Frontier wallets via **EIP-6963** standard and communicates with backend APIs to provide an in-game AI companion.

---

## Technology Stack

### React + Vite
- **React 18** — UI framework
- **Vite** — Build tool and dev server
- **TypeScript** — Type-safe component development
- **Plain CSS** — EVE Frontier gold/brown terminal styling (no framework)

### Wallet Connection
- **EIP-6963 Standard** — Multi-wallet support (MetaMask, Eve Vault, others)
- **window.ethereum** API — Standard Ethereum/EVM wallet interface
- **No custom auth** — Uses backend's simpler token validation for internal endpoints

### Deployment
- **StaticFiles mount** at `/static/companion/` on FastAPI backend
- **Production build** generated by `npm run build` → `/opt/eve-frontier/frontend/dist/`
- **Access URL:** `http://135.181.95.84:8745/static/companion/index.html`

## Architecture: What Is What

### The React App (React + Vite)

**Location:** `/opt/eve-frontier/frontend/`

A standard React application built with Vite. When you run `npm run build`, Vite:
1. Compiles TypeScript to JavaScript
2. Bundles React and dependencies
3. Minifies CSS and JS
4. Outputs production files to `dist/`

The app is **not** served by a separate Node.js server. Instead, the **compiled static files** are served by FastAPI's StaticFiles handler.

**Key files:**
- `src/App.tsx` — Main component (wallet, structures, chat)
- `src/App.css` — Styling
- `vite.config.ts` — Build configuration

### EIP-6963 Standard

**What it is:** A web standard for wallet discovery that allows web pages to connect to any wallet (MetaMask, Eve Vault, Ledger Live, etc.) without hardcoding wallet detection.

**How it works in the app:**
```typescript
// In App.tsx, handleConnectWallet()
const accounts = await (window as any).ethereum.request({
  method: "eth_requestAccounts",
});
const address = accounts[0];
```

This triggers the user's wallet provider to show a connection prompt. No custom auth code needed.

### Backend Integration

The React app makes HTTP requests to backend endpoints:

| Endpoint | Purpose | Auth |
|----------|---------|------|
| `GET /player/{wallet}/characters` | Load player character data | None required |
| `GET /structures` | List available structures | Optional X-Server-Token header |
| `POST /structure-chat` | Send message, stream AI response | None required |

**Base URL:** Set dynamically via `window.location.origin` so the app targets the same server it's served from.

## Build and Deployment Process

### Development (Local Testing)

```bash
cd /opt/eve-frontier/frontend
npm install          # Install dependencies
npm run dev          # Start Vite dev server on http://localhost:5173
```

The dev server runs with `host: '0.0.0.0'` so it's accessible from other machines at `http://135.181.95.84:5173`.

### Production Build

```bash
cd /opt/eve-frontier/frontend
npm run build        # Compile to dist/
```

This generates:
- `dist/index.html` — Entry point
- `dist/assets/index-*.js` — Bundled React + dependencies
- `dist/assets/index-*.css` — Bundled styles
- `dist/favicon.svg`, `dist/icons.svg` — Static assets

### Deployment to Static Files

```bash
cp -r /opt/eve-frontier/frontend/dist/* /opt/eve-frontier/static/companion/
```

Files are now served by FastAPI at `/static/companion/index.html`.

### Vite Base Path Configuration

The build needs to know where the app will be served from:

```typescript
// vite.config.ts
export default defineConfig({
  base: '/static/companion/',  // All asset paths use this prefix
  // ...
});
```

This ensures asset references in `index.html` are correct:
- `src="/static/companion/assets/index-*.js"`
- `href="/static/companion/assets/index-*.css"`

Without this, assets would look for `/assets/` at the web root instead of `/static/companion/assets/`.

## Wallet Connection Flow

1. **User clicks "Connect Wallet"**
   - `handleConnectWallet()` calls `window.ethereum.request({method: 'eth_requestAccounts'})`
   - User's wallet provider (MetaMask/Eve Vault) shows connection prompt
   - User approves connection

2. **Wallet Connects**
   - Backend receives wallet address
   - `loadPlayerData(address)` fetches character info from `/player/{address}/characters`
   - Character name, ID, and structure count displayed

3. **Load Structures**
   - `loadStructures()` fetches all structures from `/structures`
   - Structures dropdown populated

4. **Select Structure and Chat**
   - User selects structure from dropdown
   - User types message → `handleSendMessage()` sends to `/structure-chat`
   - Backend streams AI response via SSE (Server-Sent Events)
   - Each chunk parsed and logged to terminal

## Server-Sent Events (SSE) Response Streaming

The `/structure-chat` endpoint returns a streaming response:

```
data: {"text": "I am "}
data: {"text": "ready"}
data: [DONE]
```

The React app reads this stream:

```typescript
const reader = res.body?.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  const chunk = decoder.decode(value);
  const lines = chunk.split("\n");

  for (const line of lines) {
    if (!line.startsWith("data: ")) continue;
    const dataStr = line.slice(6).trim();
    if (!dataStr || dataStr === "[DONE]") continue;

    const data = JSON.parse(dataStr);
    if (data.text) {
      addLog(data.text, "ai");
    }
  }
}
```

This allows responses to appear incrementally as they're generated.

## API Communication

### Dynamic Base URL

```typescript
const API_BASE_URL = window.location.origin;
```

When accessed at `http://135.181.95.84:8745/static/companion/index.html`:
- `window.location.origin` = `http://135.181.95.84:8745`
- API calls go to `http://135.181.95.84:8745/player/...`, etc.

### Example API Call

```typescript
const res = await fetch(`${API_BASE_URL}/player/${address}/characters`);
const data: PlayerData = await res.json();
```

## Error Handling

The app logs all errors to the terminal with color coding:

```typescript
addLog(`❌ Error: ${error.detail}`, "error");  // Red text
addLog(`⚠️ Warning: ...`, "warning");          // Orange text
addLog(`✅ Success: ...`, "info");             // Gold text
```

Users see failures immediately in the terminal.

- **No External Dependencies:** React only, no UI framework or chart libraries
- **Streaming Responses:** Chat responses appear incrementally, not all at once
- **Static File Serving:** No server-side rendering; pure static files

## Why Not Use a Full DApp Kit?

Early in development, we considered `@evefrontier/dapp-kit`, which provides:
- Pre-built wallet connection UI
- Account discovery
- Sui-specific utilities

**Decision:** Use vanilla EIP-6963 instead because:
1. **Simpler** — One HTTP API call vs. full SDK
2. **Lighter** — No extra dependencies
3. **Flexible** — Custom UI matches our terminal aesthetic
4. **Sufficient** — EIP-6963 handles wallet discovery fully

The official DApp Kit is excellent for full dApps (transactions, contracts). For a read-only companion chat, plain JavaScript is lighter and faster.
